# UI tooling sweep: THE-96, THE-98, THE-99, THE-100

**Date:** 2026-04-27
**Branch:** `fix/the-96-98-99-100-ui-sweep`
**Linear:** THE-96, THE-98, THE-99, THE-100

## Why one PR

All four came out of the same LinkedIn-automation session and three of them touch overlapping files (`ui-query.ts`, `ui-action.ts`, `parsers/ui-dump.ts`). THE-99 *consumes* the THE-96 and THE-98 fixes — its selector path only feels good once dump coords are device-space and labels aren't dropped. THE-100 is unrelated by subject but is one line of work and specifically catches the contract drift the other three fixes will cause; bundling it earns its keep on this very PR.

## Fix 1 — THE-96: dump returns device-space coords

**Problem.** `ui-query dump` transforms every node from device-space to image-space whenever a prior `ui-capture screenshot` set a `scalingState`. Callers using `adb-shell input tap` (e.g. when `ui-action` is unavailable, as it was under THE-95) get coords that miss the target by `scaleFactor`x.

**Fix.**
1. Drop the implicit transform from the dump path. `UiAutomatorAdapter.dump` returns device-space (the native `uiautomator` output). Remove `transformTreeToImageSpace` from the dump path; keep the helper for any future caller that wants explicit conversion.
2. Add metadata to the `ui-query dump` response: `coordinateSpace: "device"`, `scaleFactor`, `deviceDimensions`, `imageDimensions` (omit when no screenshot has set scaling).
3. Flip `ui-action.tap`'s `deviceSpace` default to `true`. Description updated to: *"x/y are device-space, matching ui-query dump. Set deviceSpace:false only when passing image-space coords from a screenshot overlay."*

**Migration risk.** Any external script that read coords from old dump output and called `ui-action tap` without `deviceSpace:true` would break. No published consumers besides our own usage; documented in PR.

## Fix 2 — THE-98: propagate child text labels

**Problem.** Composite rows (LinkedIn bottom-sheet menu, list items with multiple TextViews) come back from `ui-query dump` as bare Buttons with empty `text`. Labels live on inner `TextView` children that the parser never folds up.

**Fix.** In `parsers/ui-dump.ts`, after the tree is parsed, walk depth-first post-order. For any node with empty `text` *and* empty `contentDesc`, collect descendant `text || contentDesc` values in DOM order and join with single spaces; assign to the parent's `text`. Genuine labels are never overwritten.

**Why join, not pick first.** Multi-TextView rows lose context if the first label wins. Joining is loud but lossless and matches `textContains` selectors better.

**Test.** New fixture `tests/fixtures/ui-dump/bottom-sheet-menu.xml` modelled on the LinkedIn pattern. Existing snapshots that depended on empty `text` will need to refresh.

## Fix 3 — THE-99: selector-based `ui-action`

**Problem.** `ui-action` only accepts `x,y` or `elementIndex`. When numeric input fails (THE-95), there is no escape hatch. Even on the happy path, callers are forced to call `ui-query` first and pass coords through.

**Fix.**
1. Add `selector` to `uiActionInputSchema`, mirroring `ui-query.find`'s shape: `resourceId | text | textContains | className | nearestTo`.
2. Extract `resolveSelector(selector, context, config, deviceId) → { elements, anchorCenter? }` from `handleFind` into a reusable helper in `ui-find.ts`. `handleFind` and the new `ui-action` selector path both consume it.
3. Resolution precedence: `selector` → `elementIndex` → `x/y`.
4. Match handling:
   - 0 → `ReplicantError(ELEMENT_NOT_FOUND)`, listing nearby candidates if the resolver's fallback tier produced any.
   - 1 → `tap(deviceId, centerX, centerY, /*deviceSpace*/ true)`.
   - >1 → new `ReplicantError(AMBIGUOUS_MATCH)` listing each match's `text`, `resourceId`, `bounds`. Hint: disambiguate via `nearestTo` or a tighter `resourceId`.
5. `input` op with selector: tap-to-focus first, then `input.text`. Same multi-match rules.
6. `scroll` op with selector: walk up from the matched element to the nearest ancestor whose `className` contains `ScrollView` / `RecyclerView` / `ListView`, then swipe within that container's bounds. Fall back to screen-center scroll with a warning when no scrollable ancestor exists.

## Fix 4 — THE-100: local contract guard

**Problem.** `npm run check:contracts` only runs in CI. Schema drift is discovered after pushing.

**Fix.** Rename the watcher to `test:watch`, change `test` to one-shot + contract check:

```diff
-"test": "vitest",
+"test": "vitest --run && npm run check:contracts",
+"test:watch": "vitest",
```

CI's `npm test` becomes one-shot + contract check. Daily dev gets `npm run test:watch`. The `validate` and `prepublishOnly` scripts that already pass `--run` continue to work.

## Test plan

Tests-first per fix, in this order (smallest blast radius to largest):

1. **THE-98** — bottom-sheet fixture, parser unit test asserting `Connect / Unfollow / Report` surface as `text` on parent rows.
2. **THE-96** — adapter `dump` returns device-space; `ui-query dump` response carries `coordinateSpace`, `scaleFactor`, dimensions; `ui-action.tap` default flip.
3. **THE-99** — selector resolves single match → tap; 0 matches → structured error; >1 matches → `AMBIGUOUS_MATCH`; scroll-container heuristic; coord back-compat unchanged.
4. **THE-100** — `npm test` one-shots and fails on a deliberately-stale contract.

After each fix lands its test + impl, regenerate the contract snapshot (`npm run generate:contracts`) and commit atomically.

Final: `npm run test:coverage` to confirm thresholds, then `/create-pr`.
